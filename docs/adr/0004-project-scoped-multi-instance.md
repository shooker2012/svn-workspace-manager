# 项目范围的多实例与互斥

## 状态

提议

## 背景

当前管理器只有一份配置、状态和任务记录，GUI 也使用一个全局互斥锁，因此只能打开一个 SVN 项目。现有任务映射会修改项目根目录中的 junction；两个进程同时操作同一个项目会破坏工作副本和恢复状态。

## 决策

引入“项目”作为现有任务和任务映射功能的外层边界。每个项目拥有独立的配置、状态、任务记录、操作恢复记录和日志目录。项目身份由项目根目录的规范化真实路径计算，两个不同本地 checkout 即使使用相同 SVN URL 也视为不同项目。

项目窗口绑定一个不可变的 `ProjectContext`。不同项目使用不同进程打开；同一项目只允许一个 GUI 窗口，由项目 ID 对应的 GUI session mutex 互斥。第二次打开同一项目时只显示占用提示，不尝试激活或接管已有窗口。

CLI 可以连接已经由 GUI 打开的项目。GUI 和 CLI 的每个写操作（文件复制、junction 变更、SVN 更新、任务记录或状态写入）都使用同一项目 operation mutex 串行化；操作完成后立即释放，不能由 GUI 会话长期持有。只读 CLI 查询不取得写操作锁，但必须容忍查询期间状态变化并在输出中报告读取失败或过期结果。

项目索引是应用级资源，登记最近打开的项目和显示名称。修改索引使用单独的应用级短时锁；项目运行锁不用于保护索引。项目配置、状态和任务记录使用临时文件加替换的方式原子写入，并保留 schema version。

项目根目录、任务根目录以及任务映射目录的实际影响范围不得与另一个已登记项目重叠。发现相同路径、父子路径、junction 解析后重叠或共享任务根目录时，拒绝打开并给出具体冲突路径。这样可以防止“不同项目”绕过项目 ID 后仍修改同一批文件。

现有单项目数据首次启动时迁移为一个项目；迁移过程保留原文件备份，并在迁移完成后才更新项目索引。迁移失败不得删除旧数据。

## 运行规则

- GUI 没有 `--project` 且只有一个可用项目时自动打开它；有多个项目时先显示项目选择器。
- 项目只能从已存在且可验证的 SVN 工作副本导入；项目选择器不创建空项目配置。
- CLI 支持显式 `--project <path>`；未指定时从当前目录向上查找唯一匹配项目，无法唯一确定时失败并提示指定项目。
- `status` 等只读命令允许在 GUI 打开项目时运行；写命令必须取得项目 operation mutex。GUI 打开的项目仍禁止第二个 GUI 窗口，但不阻止 CLI 连接。
- 项目路径被移动后，旧项目记录显示为“路径不存在”，由用户明确选择新路径后重新绑定，不根据 SVN URL 自动猜测。
- 关闭窗口前必须取消或完成正在运行的操作，再释放项目锁；中断操作继续由项目状态记录驱动现有修复流程。

## 影响

现有 `WorkspaceService` 的 SVN 和映射业务保持项目内语义，主要变化集中在 `WorkspaceStore`、启动流程、锁管理和 CLI 参数。Codex 上下文必须携带项目身份或从当前目录解析项目，不能再依赖全局唯一的 `config.json`。

## 未决问题

1. 写操作竞争时，CLI 是等待一段时间后失败，还是立即失败并提示 GUI 当前操作；建议默认短时等待后失败。
2. 只读 CLI 查询是否需要显示查询开始时间和项目状态 revision，避免用户误把并发查询当成事务快照。
